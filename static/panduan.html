Panduan setup

Cara menghubungkan device ke Panic Button

Semua sumber data — Meshtastic, HTTP, simulator, maupun gateway lain — bermuara ke satu registry yang sama. Panduan ini menjelaskan data apa yang harus dikirim, ke endpoint atau topik mana, dan aturan identitas tiap tipe device.

Di dashboard, titik merah berkedip berarti panic, merah statis berarti device tidak mengirim data lebih dari 1 jam (termasuk yang belum pernah kirim data), sedangkan titik biru/hijau berarti device aktif.

Base URL https://panic-button.jokocloud.my.id HTTPS 443

Status deployment

Staging panic-button.jokocloud.my.id saat ini hanya mengekspos HTTPS 443. Jalur HTTP dan WebSocket siap dipakai, tetapi broker MQTT belum dapat dijangkau langsung dari internet. Di server staging, Mosquitto menyediakan MQTT TLS 8883 dengan autentikasi untuk device di jaringan lokal.

Aktif

HTTP API & WebSocket

Ingest, registrasi device, panic/resolve, dan dashboard realtime tersedia lewat https://panic-button.jokocloud.my.id dan wss://panic-button.jokocloud.my.id/ws.

Staging siap, publik tertutup

MQTT Meshtastic

Server staging membuka 8883 dengan TLS + username/password, sedangkan 1883 tetap anonim untuk internal. Port MQTT belum diekspos ke internet; gateway publik belum bisa terhubung sampai jalur jaringan disiapkan.

Pilihan agar Meshtastic bisa terhubung Hubungkan gateway ke broker staging lewat LAN dengan TLS 8883, gunakan MQTT Client Proxy + VPN, atau buka port MQTT di firewall dengan pembatasan. Detail dan kredensial ada di bagian Meshtastic.

Identitas device

Setiap device harus punya satu identitas stabil. Server memakai id sebagai kunci state live dan penyimpanan konfigurasi.

Jenis Nilai Aturan

Device ID bebas truck-01 Huruf, angka, dan ! - _ . :, maksimal 64 karakter.

HTTP / device kustom

Semua perangkat yang bisa mengirim HTTP JSON dapat memakai satu endpoint yang sama: POST https://panic-button.jokocloud.my.id/api/ingest. Untuk format tracker umum, gunakan auto-detect GET/POST https://panic-button.jokocloud.my.id/api/ingest/auto.

Panic & resolve tanpa payload posisi

Jika device sudah dikenal server dan sudah punya posisi terakhir, panic bisa dipicu tanpa mengirim lat/lon:

curl — panic / resolve 
# Tandai panic memakai posisi terakhir
curl -X POST https://panic-button.jokocloud.my.id/api/devices/truck-01/panic

# Tandai panic selesai
curl -X POST https://panic-button.jokocloud.my.id/api/devices/truck-01/resolve

Keduanya mengembalikan 404 jika device belum pernah terdaftar atau belum pernah mengirim data. Panic tidak hilang karena update posisi; harus di-resolve eksplisit lewat endpoint ini, event panic_clear, atau detection_sensor dengan state: false.

WebSocket realtime

Dashboard memakai wss://panic-button.jokocloud.my.id/ws. Saat terhubung, server mengirim snapshot, lalu stream perubahan. Integrasi kustom dapat memakai protokol yang sama.

Tipe pesan Payload Kapan dikirim
snapshot devices[] Saat client connect atau tertinggal dari stream.
update device Update posisi, telemetry, metadata, atau status normal.
panic device Transisi normal → panic.
panic_cleared device Panic diselesaikan.
removed id Device dihapus lewat API/UI.
raw_captured device_key, count Ada payload baru yang belum didukung.
Reverse proxy Jika dashboard di belakang proxy HTTPS, pastikan path /ws meneruskan header Upgrade dan Connection. Tanpa itu, dashboard tampil tetapi status koneksi tetap Offline.

Payload belum didukung

Klik Data Mentah di dashboard untuk melihat payload MQTT atau /api/ingest/auto yang tidak cocok dengan adapter, atau gagal diproses (misalnya paket protobuf Meshtastic yang tidak bisa didekripsi). Payload dikelompokkan per device berdasarkan ID pada topik/body, dengan fallback ke topik. Riwayat disimpan di data/unmatched.json maksimal 500 entri, 50 per device, 8 KB per payload, dan 7 hari.

Kunci sensitif seperti password, token, dan authorization diganti *** sebelum disimpan. Payload biner ditampilkan dalam base64.

Method Path Keterangan
GET /api/unmatched Daftar device beserta jumlah payload.
GET /api/unmatched/payloads?key=... Riwayat payload satu device, terbaru dulu.
DELETE /api/unmatched?key=... Hapus riwayat satu device; tanpa key hapus semua.

Meshtastic (MQTT)

MQTT TCP publik belum reachable; WebSocket tersedia dengan konfigurasi Domain panic-button.jokocloud.my.id mengekspos 443 untuk HTTP/WebSocket. Broker staging membuka 8883 (TLS + auth), 1883 (anonim, internal), dan 9001 (MQTT over WebSocket). Native TCP 8883/1883 belum diekspos ke internet. Listener 9001 dapat dijangkau sebagai wss://mqtt-panic-button.jokocloud.my.id setelah route Cloudflare ke http://mosquitto:9001 dibuat. Untuk device di LAN, gunakan IP-LAN:8883.

Prasyarat perangkat

  • Gunakan gateway berbasis ESP32 (T-Beam, Heltec V3, T-Deck, dll). Board nRF52 seperti RAK dan T-Echo tidak menyediakan modul MQTT.
  • Firmware 2.7.x dengan JSON Output aktif, atau firmware 2.8+ yang mengirim protobuf. Server mendukung topik JSON /2/json/ maupun protobuf /2/e/ dan legacy /2/c/.
  • Gateway punya koneksi jaringan ke broker, baik langsung, lewat VPN, maupun melalui MQTT Client Proxy di HP.
  • Untuk listener 8883: username user dan password dari mosquitto/.mqtt-password (dibuat dengan make mqtt-setup).

Format pesan: JSON vs protobuf

  • JSON — topik msh/<region>/2/json/<channel>/<node>. Paket position, nodeinfo, telemetry, text, dan detection_sensor diproses langsung.
  • Protobuf — topik msh/<region>/2/e/<channel>/<node> (atau /2/c/). Paket decoded diproses tanpa PSK; paket channel terenkripsi didekripsi dengan PSK default AQ== atau MESHTASTIC_PSK.
  • PKI — topik /2/e/PKI/<node> memakai X25519 + AES-256-CCM dan tidak bisa didekripsi tanpa private key node. Server mencatat peringatan lalu melewatinya. Minta node mengirim posisi sebagai broadcast di channel biasa.
  • PSK custom dapat dilihat di aplikasi Meshtastic: Settings → Radio Config → Channels → PSK, atau CLI meshtastic --ch-index 0 --ch-get psk. Isi MESHTASTIC_PSK dengan nilai base64; beberapa PSK dipisahkan koma.

Opsi jalur jaringan

  1. Hubungkan lewat LAN dengan TLS 8883. Server staging sudah menyediakan listener 8883 dengan TLS dan username/password. Arahkan gateway ke IP-LAN:8883, aktifkan TLS, lalu isi kredensial dari mosquitto/.mqtt-password. Sertifikat bersifat self-signed; firmware Meshtastic memakai setInsecure sehingga tetap bisa terhubung.
  2. MQTT Client Proxy + VPN (tanpa buka port). Aktifkan MQTT Client Proxy di aplikasi Meshtastic, hubungkan HP ke VPN yang bisa mencapai server, lalu arahkan MQTT server ke IP privat server. Gateway meneruskan trafik lewat HP.
  3. Buka port MQTT dengan firewall. Utamakan port 8883 (TLS + auth) dan batasi sumber IP seketat mungkin. Hindari mengekspos 1883 ke internet terbuka karena trafiknya plaintext dan anonim; port itu hanya untuk jaringan internal.
  4. MQTT over WebSocket (WSS) via Cloudflare. Broker menyediakan listener 9001 dengan protokol WebSocket dan autentikasi. Arahkan public hostname Cloudflare ke service http://mosquitto:9001; edge Cloudflare menyediakan wss://. Cocok untuk aplikasi Meshtastic yang mendukung URI wss://host/mqtt (gunakan MQTT Client Proxy). Node dengan Wi-Fi/Ethernet sendiri umumnya tetap memakai TCP.

Setup aplikasi Meshtastic (MQTT over WebSocket)

  1. Update aplikasi Meshtastic ke versi terbaru yang memakai MQTTastic client.
  2. Buka Settings → Module config → MQTT, aktifkan MQTT.
  3. Jika node tidak punya internet sendiri, aktifkan MQTT Client Proxy agar HP meneruskan trafik.
  4. Isi Address dengan URI lengkap wss://mqtt-panic-button.jokocloud.my.id.
  5. Isi username user dan password dari mosquitto/.mqtt-password.
  6. Aktifkan uplink/downlink pada channel, lalu Save & Send.
  7. Pastikan Cloudflare memiliki route WSS ke listener 9001 sebelum koneksi diuji.

Catatan: node dengan Wi-Fi/Ethernet sendiri umumnya tetap memakai MQTT TCP (8883), bukan WebSocket.

Tes koneksi TLS

bash — subscribe via TLS 
docker exec -it panic-button-mosquitto-1 mosquitto_sub \
  -h 127.0.0.1 -p 8883 \
  --cafile /mosquitto/certs/server.crt \
  -u user -P "$(cat mosquitto/.mqtt-password)" \
  -t 'msh/+/2/json/+/#' -v

Publish manual untuk menguji jalur device ke server:

bash — publish via TLS 
docker exec -it panic-button-mosquitto-1 mosquitto_pub \
  -h 127.0.0.1 -p 8883 \
  --cafile /mosquitto/certs/server.crt \
  -u user -P "$(cat mosquitto/.mqtt-password)" \
  -t 'msh/ID/2/json/Panic/!test' \
  -m '{"from":53261,"type":"position","payload":{"latitude_i":-62000000,"longitude_i":1068000000}}'

Topik dan payload

Gateway mempublikasikan JSON ke msh/<region>/2/json/<channel>/<userid>. Server berlangganan MQTT_TOPIC (default msh/#) serta MQTT_TRACKING_TOPIC (default gps/#, dipakai saat MQTT_TOPIC dibatasi). Topik tambahan dapat dikelola lewat menu Topik MQTT, lalu menurunkan Device ID Meshtastic dari field from (desimal) menjadi !xxxxxxxx.

Type Field yang dipakai Aksi
nodeinfo payload.longname, shortname Menyimpan nama device.
position latitude_i, longitude_i, ground_speed, ground_track, battery_level Update posisi. Koordinat dikali 1e-7; speed m/s dikonversi ke km/jam.
telemetry payload.battery_level Update baterai.
detection_sensor payload.state atau detected true memicu panic, false menyelesaikan panic.
text payload.text Panic jika teks mengandung PANIC atau SOS (case-insensitive).

Contoh payload JSON yang diproses server:

JSON — position / panic / text 
{"from":10633728,"type":"position","payload":{"latitude_i":-62000000,"longitude_i":1068000000,"ground_speed":5.0}}
{"from":10633728,"type":"detection_sensor","payload":{"state":true}}
{"from":10633728,"type":"text","payload":{"text":"PANIC"}}

Teltonika

Listener TCP Teltonika belum tersedia Repo ini baru menyimpan protocol: "teltonika" sebagai metadata. Belum ada listener TCP atau codec AVL Teltonika, jadi jangan mengarahkan perangkat ke port TCP apa pun di server ini.

Workaround: forward lewat HTTP

Gunakan gateway/middleware yang menerjemahkan protokol Teltonika menjadi JSON, lalu kirim ke POST /api/ingest dengan IMEI sebagai device_id. Daftarkan perangkat lebih dulu dengan protocol teltonika.

json — ingest via perantara 
{
  "device_id": "357123456789012",
  "lat": -6.2,
  "lon": 106.8,
  "speed_kmh": 35.0,
  "heading": 120,
  "battery": 88,
  "event": "heartbeat"
}
curl — forward ke API 
curl -X POST https://panic-button.jokocloud.my.id/api/ingest \
  -H 'content-type: application/json' \
  --data-binary @payload.json

Jika ingin dukungan native Teltonika (TCP + codec AVL), itu fitur terpisah: listener baru harus menormalisasi data ke IngestEvent yang sama agar API dan UI tidak berubah.

Troubleshooting

Gejala Penyebab umum Solusi
400 device_id wajib diisi ID kosong dan serial bukan IMEI valid. Isi device_id atau serial/IMEI 15–16 digit.
422 invalid coordinates Lat/lon tidak berpasangan, di luar rentang, atau 0,0. Kirim keduanya dengan nilai valid.
Device ada tapi tidak di peta Baru diregistrasi tanpa posisi, atau ingest belum pernah masuk. Kirim POST /api/ingest dengan lat/lon.
409 serial/IMEI already registered Serial dipakai device lain. Cari IMEI di modal Kelola Device, lalu edit device tersebut.
Status WebSocket Offline Reverse proxy tidak meneruskan Upgrade, atau server mati. Periksa konfigurasi proxy /ws dan /health.
Device Meshtastic tidak muncul Topik/region salah, port MQTT tertutup, kredensial/TLS salah, PSK channel custom, atau paket hanya PKI. Cek topik /2/json/ atau /2/e/, konektivitas broker, kredensial 8883, dan MESHTASTIC_PSK. Untuk PKI, minta node mengirim broadcast di channel biasa.
Tracker GPS MQTT tidak muncul Topik bukan gps/# atau payload tidak memiliki lat/lon. Publish ke gps/<device_id> atau sesuaikan MQTT_TRACKING_TOPIC.
MQTT terhubung tapi data kosong Channel uplink mati atau root topic berbeda. Aktifkan uplink dan samakan root topic/region/channel.
Suara alarm tidak berbunyi Browser memblokir audio sebelum interaksi pengguna. Klik tombol Suara: OFF sekali untuk mengaktifkan.
Panic tidak selesai Update posisi tidak menghapus panic. Kirim panic_clear, detection_sensor state:false, atau panggil /resolve.

Keamanan

Deployment ini publik Tidak ada autentikasi pada API dan CORS terbuka. Broker MQTT 1883 anonim untuk jaringan internal, sedangkan 8883 memakai TLS + username/password. Siapa pun yang bisa menjangkau endpoint API dapat membaca data, membuat device, memicu panic, atau menghapus device.
  • Jangan gunakan untuk data sensitif tanpa menambahkan autentikasi dan otorisasi.
  • Batasi akses API di reverse proxy/firewall, minimal untuk operasi tulis.
  • Jangan membuka MQTT 1883 ke internet terbuka; gunakan 8883 (TLS + auth), WSS mqtt-panic-button.jokocloud.my.id, VPN, atau ACL.
  • JSON MQTT tidak dienkripsi end-to-end; pada listener 1883 payload juga plaintext di jaringan. Siapa pun yang memegang kredensial 8883 dan akses broker dapat membaca pesan panic dan posisi.
  • Server masih berlangganan ke broker lewat 1883 di jaringan Docker. Untuk produksi, pertimbangkan mqtts:// untuk subscriber, API auth, dan pencatatan audit.

Panduan ini mengikuti implementasi repo panic-button. Kembali ke dashboard.
